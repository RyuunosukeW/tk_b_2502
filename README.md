# サンプル（プロダクト名）
  Forgotten Food

[![IMAGE ALT TEXT HERE](https://jphacks.com/wp-content/uploads/2025/05/JPHACKS2025_ogp.jpg)](https://www.youtube.com/watch?v=lA9EluZugD8)

## 製品概要
  スマホで食品パッケージやラベルを撮るだけで、サーバ側AIが「食品判定」と「期限抽出」を実施。合格データのみアプリに保存し、期限が近づくと通知で知らせる“フード管理ミニマル基盤”。（Android/Kivy アプリ + FastAPI ゲートウェイ + Postgres）
### 背景(製品開発のきっかけ、課題等）
  家庭内の食品ロスは「把握の手間」と「気づきの遅れ」が主因。
  既存アプリは手入力やバーコード依存が多く、継続が難しい。
  撮影→自動判定→期限通知までを最小の操作と確実な品質ゲートで実現することを目的化。
### 製品説明（具体的な製品の説明）
  アプリから撮影/ギャラリー選択 → 自動アップロード → AI解析 → 保存の一連を自動実行。
  サーバは食品かどうか（is_food）と信頼度を推定。基準（0.72）を超えたものだけを accept として保存。
  期限（賞味/消費）を画像から抽出できた場合に限り登録。
  端末のローカルDB（SQLite）に一覧表示・検索・サムネイル表示。期限が近いものは通知。
### 特長
  品質ゲート一体化：非食品/低信頼はそもそも保存しないためデータが汚れない。
  フロント軽量主義：スマホ側は表示と保存のみ。判定権限はすべてサーバに集約。
  通知まで自律：バックグラウンドで期限を巡回、OS通知で“今やるべき”を提示。

### 解決出来ること
  手入力なしで数秒登録、面倒さを削減。
  “誤登録”を構造的に防止（非食品や曖昧画像を排除）。
  期限間近の取りこぼし防止（定期チェック＋通知）。
### 今後の展望
  通知タップで**「期限間近」画面へ直行**するUX強化。
  ジョブストアの永続化/TTL管理で再起動に強い非同期処理へ。
  サムネイルURLの絶対URL化、CIでの契約テスト整備。
### 注力したこと（こだわり等）
* accept-only の明確な入庫条件で品質と説明責任を両立。
  モバイルのネットワーク変動を前提に、同期/202+ポーリングの両系を許容。
  すべての呼び出しに X-Request-ID を通し、トレース容易化。
* 

## 開発技術
  AI：OpenAI ビジョン（既定: GPT-5、失敗時フォールバック）
  サーバ：FastAPI、Postgres、画像アップロード（image/* のみ、サイズ上限/レート制御）
  モバイル：Python 3.11、Kivy、Buildozer、SQLite、OS 通知（Plyer）

観測/運用：X-Api-Key、X-Request-ID、レートリミティング
### 活用した技術
#### API・データ
* モバイル向け REST：/api/v1/uploads → /api/v1/analyze（同期 or 202+/api/v1/jobs/{id}）→ /api/v1/items（accept のみ保存）
  healthz で稼働モデル名を返却。サムネイルは thumb_url を優先利用。
  端末DB：label / expiry_date / image_path / confidence / label_raw / topk_json / thumb_path 等を保持（非食品はそもそも入庫しない）。
* 

#### フレームワーク・ライブラリ・モジュール
* FastAPI / SQLAlchemy、Kivy / python-for-android / Buildozer、Plyer、（インフラ）Caddy など。
* 

#### デバイス
* Android（API 23+）想定。arm64-v8a を主ターゲットにデバッグビルド。
* 

### 独自技術
#### ハッカソンで開発した独自機能・技術
* 食品ゲートの決定規則：is_food=false → reject-non_food、is_food=true かつ信頼度≥0.72 → accept、その他→ reject-low_conf。
  入庫設計：decision=accept のみ保存する一方向ゲートでデータ品質を担保。
  UI/UX：撮影→登録までの待機を最小化し、失敗時は保存そのものを抑止。
  ハッカソンで開発した独自機能・技術
  サーバ主導の画像解析パイプライン（モバイルは薄く、権威はサーバ）。
  通知連動の近期限フィルタ（ローカルDB走査→OS通知）。
  縮小画像連携（thumb_url が無い場合は端末側で生成・保持）。
  独自で開発したものの内容
  モバイル用 /api/v1 ミニマル設計、同期/非同期の両対応。
  端末DBスキーマの説明可能性フィールド（confidence/label_raw/topk_json 等）を追加。
